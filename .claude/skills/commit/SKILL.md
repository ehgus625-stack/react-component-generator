# commit

변경사항을 분석하여 컨벤션에 맞게 커밋하는 스킬.

## 절차

### 1. 변경사항 분석
- `git status`로 변경/추적되지 않은 파일을 확인한다.
- `git diff`(unstaged)와 `git diff --staged`(staged)로 실제 변경 내용을 읽는다.
- 새 파일(untracked)은 내용을 직접 읽어 성격을 파악한다.
- `git log --oneline -10`으로 기존 커밋 스타일을 참고한다.
- 변경사항이 없으면 그 사실만 알리고 종료한다.

### 2. 논리적 단위로 분류
- 하나의 목적/관심사 단위로 변경을 묶는다. 서로 다른 성격(기능 추가 + 리팩터링 + 설정 변경 등)은 별도 커밋으로 나눈다.
- 각 커밋에 포함할 파일 목록을 정한다. 한 파일 안에 여러 관심사가 섞였으면 사용자에게 알린다.
- `.env`, 키/토큰, `node_modules`, 빌드 산출물 등 커밋하면 안 되는 파일은 제외하고 경고한다.

### 3. 커밋 메시지 작성
형식: `타입: 요약` (한국어, 요약은 50자 내외, 마침표 없음)

| 타입 | 용도 |
|------|------|
| feat | 새로운 기능 추가 |
| fix | 버그 수정 |
| refactor | 동작 변화 없는 코드 구조 개선 |
| chore | 설정, 의존성, 빌드, 문서 등 기타 작업 |

- 무엇을 했는지가 아니라 **왜/무엇이 달라졌는지**가 드러나게 쓴다.
- 필요하면 빈 줄 뒤에 본문(변경 이유, 주요 내용)을 덧붙인다.

### 4. 즉시 커밋 (기본값: 승인 없이 진행)
- 기본 동작은 승인 없이 진행이다. 사용자의 커밋 요청 자체가 승인이므로, 별도 확인 없이 바로 커밋한다.
- 커밋 단위별로 파일을 개별 지정해 `git add <파일...>` 후 `git commit`을 실행한다. (`git add -A`/`.` 지양)
- 완료 후 `git log --oneline`으로 커밋별 메시지와 포함 파일을 보고한다.
- 승인 단계는 사용자가 "확인하고 커밋", "먼저 보여줘"처럼 명시적으로 요청한 경우에만 켠다(opt-in). 이때는 커밋별 메시지와 파일 목록을 보여주고 승인 후 실행한다.
- 시크릿 등 제외 대상 의심 파일은 묻지 않고 커밋에서 제외한 뒤, 결과 보고에 제외 사실과 이유를 함께 알린다.

## 금지 사항
- `git push`, `--amend`, `--no-verify`, 강제 옵션은 사용자가 요청하지 않는 한 사용하지 않는다.
- pre-commit 훅이 실패하면 원인을 수정하고 새 커밋으로 진행한다.
